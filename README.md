## 问题背景

### 场景一：活动落地页管理后台设计

> 假设你负责设计 Insta360 官方商城的活动落地页管理后台，请基于以下业务场景，设计一套活动落地页管理方案，目标是**提升运营配置效率**，并**降低因配置错误导致的线上问题**。

**需求背景：**

目前商城会针对不同国家/地区开展不同活动，例如国内 618、海外 Prime Day、Black Friday、开学季等。运营人员需要提前配置活动落地页，主要存在以下场景：

1. 不同活动会使用不同的页面主题样式，例如 Prime Day 为蓝色主题、Black Friday 为黑色主题；同一活动主题下，不同国家/地区可以复用相同的页面样式。
2. 同一活动主题在不同国家/地区的上线、下线时间可能不同，需要支持活动开始时自动上线，结束后自动下线。例如英国、西班牙 8 月 20 日上线，德国 8 月 25 日上线。
3. 同一活动下，不同国家/地区展示的活动商品、赠品、活动文案及文案语言可能不同。
4. 活动页面需要提前完成配置，并支持运营人员内部预览 PC 和 Mobile 端页面效果，但在正式生效前不能被用户访问。

**产出物：**

1. 一份用户问题与产品定位说明，能支撑读者判断优先场景及其价值
2. 一份产品需求文档，能支持设计与研发理解如何实现需求
3. 一个可交互可演示的网页 Demo，能展示所有典型场景下的完整体验
4. 一份评测与灰度方案，能判断该活动管理页价值是否成立

### 场景二：影石官方商城体验分析

> 请访问影石官方商城，深度体验后，从"选购—下单—履约—售后"的任一环节中，选择一个你认为设计得最好和一个你认为存在疑惑的功能，分别说明原因，并提出优化方案。
>
> 注：以海外英语地区为参考，可优先体验 Insta360 X5 产品页及购买流程。

## 方案核心思路（30 秒版)

将配置对象抽象为三层模型——**活动 Campaign → 主题模板 Theme → 国家实例 Instance**：

- **主题层**解决"重复劳动"：样式资产配一次、多国多活动复用（场景 1）
- **实例层**解决"差异化"：每个国家实例独立持有排期、语言、商品、赠品、文案（场景 3）
- **状态机 + 定时任务**解决"人工盯表"：实例按目标国当地时间自动上线/下线（场景 2）
- **预览签名链接 + C 端路由只放行"进行中"实例**解决"盲发布"：内部可随时预览，用户永远看不到未生效页面（场景 4）
- **四道防错防线**（录入校验 → 冲突检测 → 发布前检查清单 → 灰度与回滚）兜住配置错误
